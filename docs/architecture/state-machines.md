# State machines in Lamezia Trasparente

Audit scope: issue #1843. This is a source audit, not a claim of exhaustive runtime verification. A machine is a set of meaningful states, events and transition rules; a React boolean alone is only a candidate. Keep independent state independent. Prefer discriminated unions for mutually exclusive states, pure transition functions for coupled state, and existing query/router libraries for the lifecycles they already own. Do not add a global state-machine framework merely to wrap every hook.

## Reproducible evidence

Run `node scripts/architecture/stateMachineInventory.mjs --write` to regenerate [the machine-readable source index](state-machine-inventory.json). Run without `--write` to check it. It records files, line numbers and symbols for state hooks, query/mutation hooks, persisted state, timers/cancellation and state discriminants across web, mobile, API, shared libraries and scripts. Generated directories, dependencies, tests and build outputs are excluded. An entry is evidence to review, not a separate machine or a confirmed defect. State held in providers, PostgreSQL, external services, computed strings, SQL and arbitrary assignments can escape this detector. Regenerate after source changes; line numbers are edition-specific.

## WebMCP transition contract

- `start(requestId)` creates `running`; a later start supersedes UI ownership across all four tools.
- Success/failure can complete only that running request. Obsolete completions still settle their caller's promise but cannot change route or activity.
- `dismiss` hides that request's panel. Its eventual completion cannot reopen it; a new request can. Dismissal does not cancel the read or its intended navigation.
- Registration cleanup aborts transport and suppresses callbacks/navigation, including transports that resolve after cancellation.
- Errors retain promise rejection; no successful activity/navigation is emitted on HTTP failure. Failed state contains safe static copy, never response bodies.
- Successful payloads preserve existing fields and add `uiApplied: boolean`. This reports navigation ownership, not equivalence between API filters and local page state.
- Explicit empty `data` / `projects` arrays report zero. Missing list shape remains unknown (`null`). PNRR inspection requires an exact CUP result before reporting a single record.
- Read-only annotations, tool names, input schemas, endpoint paths and civic/legal caveats remain in place.

## Priorities after this change

1. Unify URL/filter transitions for PNRR and contracts across human and agent entry points; define a shared parser/serializer and back/forward tests before adapting tools.
2. Extend URL restoration tests to additional per-page filters; palette query/status/results ownership and stale-selection regression coverage are implemented here.
3. Give helper loading a tagged error/retry lifecycle and prevent late updates after unmount.
4. Audit editor draft/upload/submit identity and ingestion concurrency with database-backed integration coverage before modifying writes.

The safest architecture is local, explicit ownership at each boundary. The inventory and these contracts give humans and agents a shared entry point; they do not authorise an agent to bypass authentication, editorial review or source verification.
